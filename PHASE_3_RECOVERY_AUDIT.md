## 1. Current Architecture Overview

SAMUDRA AI is built as a hybrid agentic architecture with a **Fast Path ⚡** for low-latency factual/chitchat lookups and a **Deep Path 🧠** powered by a multi-agent LangGraph workflow.

```
USER QUERY
    │
    ▼
Fast/Deep Router (graph.py)
    ├── FAST PATH ⚡ ────────────► fast_responder_node ──► summarizer ──► translate_out ──► END
    └── DEEP PATH 🧠
          │
          ▼
    language_detection ──► intent_router ──► planner ──► location_resolver
          │
          ├──► ocean_data_collector
          ├──► weather_data_collector
          ├──► marine_data_collector
          ├──► fishery_data_collector
          ├──► geofence_data_collector
          ├──► tide_hazard_data_collector
          └──► route_data_collector
                │
                ▼
         anti_hallucination_gate (PASS / RECHECK / BLOCKED)
                │
                ▼
         risk_assessment (Deterministic Marine Risk Engine)
                │
                ├──► ocean_reasoner
                ├──► weather_reasoner
                ├──► fishery_reasoner
                └──► safety_reasoner
                      │
                      ▼
               synthesizer ──► summarizer ──► translate_out ──► END
```

## 2. Actual Request/Response Flow

1. **Frontend Request:**
   - User types a query in `InputComposer.tsx`.
   - `AppLayout.tsx` invokes `startChatStream()` in `web/src/api/sse.ts`, sending a GET request to `/chat/stream?message=...&conversation_id=...`.
2. **Backend Execution:**
   - `samudra_api.py` receives `/chat/stream`, creates/loads conversation metadata via `ConversationStore`, and streams SSE events from `graph.astream()`.
   - State graph executes nodes sequentially and in parallel.
3. **SSE Event Emission:**
   - `event: start` — Emits `conversation_id`, `thread_id`, and initial `query`.
   - `event: node` / `event: agent_step` — Emits node execution updates formatted by `build_node_thought()`.
   - `event: artifact` — Emits UI artifacts as they are generated by graph nodes.
   - `event: response` — Emits incremental synthesized text snippets.
   - `event: done` — Emits final execution result, full response, active context, and final artifacts.
4. **Frontend Consumption & Rendering:**
   - `AppLayout.tsx` updates `messages` state with assistant message containing `agentSteps`, `artifacts`, and `content`.
   - `ChatMessageItem.tsx` renders `AgentStreamCard`, response text markdown container, `ArtifactRenderer`, and `EvidencePanel`.

## 4. Lifecycle Analyses

### A. Conversation Lifecycle
- Persistent conversation IDs stored in `samudra_storage.db` using `ConversationStore` (SQLite table `conversations`).
- Multi-turn checkpoint state persisted by LangGraph `SqliteSaver` checkpointer using `thread_id` equal to `conversation_id`.
- Creating a new chat clears local UI state in `AppLayout.tsx` (`setActiveConvId(undefined)`); the next request auto-generates a new conversation UUID.

### B. History Lifecycle
- `GET /conversations` retrieves lightweight conversation list sorted by `updated_at DESC`.
- `GET /conversations/{id}` retrieves checkpoint values including `messages`, `active_context`, and `artifacts`.
- **Current Bug:** In `AppLayout.tsx`, loading history attached all conversation artifacts to the *last message only* (`idx === detail.messages.length - 1 ? detail.artifacts : []`), losing per-turn artifact association when re-opening past chats.

### C. Artifact Lifecycle
- Nodes or `translate_out_node` generate standardized artifact dictionaries using `tools/artifact_factory.py`.
- **Current Bug:** `translate_out_node` automatically appends every artifact for which data exists (PFZ, Risk, Weather, Ocean, Tide, Hazard, Geofence, Route) regardless of query intent, leading to UI clutter.
- Mismatches exist between backend dictionary keys and frontend component expectations.

### D. Map Lifecycle
- Maps rendered via `PFZMapCard.tsx` and `RouteMapCard.tsx`.
- **Current Bug 1:** `index.html` loads Leaflet CSS, but NOT Leaflet JS! `RouteMapCard.tsx` checks `const L = (window as any).L; if (!L) return;`, causing silent failure where maps never load.
- **Current Bug 2:** `PFZMapCard.tsx` had NO Leaflet map element at all—only a text list of coordinates.
- **Coordinate Order:** GeoJSON specifies `[longitude, latitude]`; Leaflet expects `[latitude, longitude]`.

### E. LLM Call Flow
- LLM calls centralized via `graph/llm.py` (`LLMProviderManager`), wrapping Gemini 3.6 Flash / Ollama / OpenAI providers with automatic fallback and circuit breaking.
- Prompts centralized in `prompts/system_prompts.py`.

### F. Agent Execution Flow
- Graph routes dynamically between FAST path (simple queries, greetings, direct lookup) and DEEP path (multi-domain, safety, navigation, risk, complex reasoning).
- In DEEP path, collectors fan out in parallel, gather evidence, pass through anti-hallucination gate, calculate deterministic risk, fan out to 4 specialist reasoners, synthesize in English, summarize context, and translate to user's language.

## 5. Summary of Key Failures & Root Causes

| # | Issue / Failure | Root Cause | Files Responsible |
|---|---|---|---|
| 1 | **Maps do not render** | Leaflet JS `<script>` missing in `index.html`. `RouteMapCard.tsx` uses `(window as any).L` which fails silently. `PFZMapCard.tsx` lacks map container. | `web/index.html`, `web/src/components/artifacts/RouteMapCard.tsx`, `web/src/components/artifacts/PFZMapCard.tsx` |
| 2 | **Artifact fields show `N/A`** | Schema mismatch between backend `create_ocean_conditions_artifact` & `create_tide_card_artifact` output keys and frontend `OceanCard.tsx` & `TideCard.tsx` input expectations. | `tools/artifact_factory.py`, `web/src/components/artifacts/OceanCard.tsx`, `web/src/components/artifacts/TideCard.tsx`, `web/src/components/artifacts/WeatherCard.tsx` |
| 3 | **Over-generation of artifacts** | `translate_out.py` forces insertion of all 8 artifact types if data is present, ignoring query intent & relevance. | `graph/nodes/translate_out.py` |
| 4 | **Rigid/Report-like responses** | System prompts in `prompts/system_prompts.py` and `SYNTHESIZER` historically used structured section templates. Need fluid, conversational adaptive responses. | `prompts/system_prompts.py`, `graph/nodes/synthesizer.py` |
| 5 | **History loads artifacts incorrectly** | `AppLayout.tsx` assigns all stored conversation artifacts to the final message upon restoring history. | `web/src/components/layout/AppLayout.tsx`, `api/samudra_api.py` |
| 6 | **Agent Execution UI lacks hierarchy & timing** | `AgentStreamCard.tsx` displays flat list without execution duration summary (`Analyzed in X.Xs`) or nested expandable agent groups. | `web/src/components/chat/AgentStreamCard.tsx`, `api/samudra_api.py` |
| 7 | **Contextual follow-up reference resolution** | Relative queries ("there", "closest one", "tomorrow", "show me the route") need robust context resolution in `planner.py`, `location.py`, and `fast_responder.py`. | `graph/nodes/location.py`, `graph/nodes/planner.py`, `graph/nodes/fast_responder.py` |

## 6. Proposed Fix Plan

1. **Fix Map Rendering & Carto Tile Integration:**
   - Import `L` directly from `'leaflet'` in React components (`import L from 'leaflet'`).
   - Add proper container refs, dimensions, CSS import, and coordinate handling (`[lat, lon]`).
   - Integrate map view into `PFZMapCard.tsx` and `RouteMapCard.tsx` with Carto Voyager/Dark tile provider and markers/polylines.
2. **Standardize Artifact Data Contracts & Eliminate Fake N/A:**
   - Fix `OceanCard.tsx` to align with `data.temperature`, `data.salinity`, `data.currents`, `data.waves`.
   - Fix `TideCard.tsx` to align with `data.current.sea_level_m`, `data.current.phase`, `data.current.trend`.
   - Replace generic fallback strings with clear data status ("Unavailable from source").
3. **Smart Artifact Selection in Backend:**
   - Update `translate_out_node` to check query intent and domains requested by `planner` before attaching artifacts (e.g., attach `pfz_map` for fishery queries, `weather_card` for weather queries, `route_map` for route queries).
4. **Natural Conversational AI Prompting:**
   - Refine `SYNTHESIZER` prompt and node output logic so responses adapt to context naturally without rigid section headers.
5. **Real ChatGPT-like Conversation History & Title Generation:**
   - Persist messages with their specific turn artifacts in database checkpointing.
   - Update `AppLayout.tsx` to correctly map artifacts to individual assistant turns.
   - Ensure clean deterministic title generation on first query.
6. **Enhanced Agent Thinking UI:**
   - Upgrade `AgentStreamCard.tsx` to show total execution time, collapsible agent groups (Marine Intelligence, Ocean Agent, Weather Agent, Safety Agent), and individual step details.
